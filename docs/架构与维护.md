# 架构与维护

这个仓库是一套给小朋友讲知识点的动画。页面在浏览器里打开，课堂投屏、自己看都可以。维护目标就三件：动画和人教版课本对得上，别人用 AI 接着加也不会把目录弄乱，做好的页面能单独发给人看。

## 三份东西不要混

| 位置 | 是什么 | 谁改 |
| --- | --- | --- |
| `main` 分支里的源码 | 可读的动画、语音、`meta.json` | 改动画只改这里 |
| `release/` | `npm run build` 生成的分享版，已混淆，不提交 | 不要手改 |
| `gh-pages` 分支、GitHub Releases | 在线站和离线压缩包 | 确认 `release/` 没问题后再发布 |

在线地址：<https://luckinov.github.io/learn-anew/>

网上和压缩包是混淆过的，方便转发，不方便改。改完要重新构建，再发布。不要直接改 `gh-pages` 上的文件。

现在没有自动部署。构建和发布分成两步，是为了没看过的页面不会直接上网。

## 一个知识点一个文件夹

```
states-of-matter/
  meta.json     课本标注、哪些页上线
  3d.html       在线页面
  index.html    只放进下载压缩包
  voice/        这一页用到的语音
```

文件夹名用英文小写和短横线，例如 `states-of-matter`。样式和脚本写在同一个 html 里。不要为新动画再加一套打包脚本，也不要引入 React 之类的框架。根目录的 `build.mjs` 会扫描这些文件夹。

`states-of-matter/build.mjs` 是早先只打包平面版用的，新动画不要照着再复制一份。

课本信息只放在 `meta.json`。构建时写进首页卡片，也写进 `release/catalog.json`。不要把年级写进动画画面，避免两处以后对不上。

## 课本怎么标

只标人教版。年级和科目可以笼统，允许写「中年级」「高年级」「不限年级」。

不要写第几单元、第几课、第几页。册次会随教材修订变化，编出来以后很难发现。

`对应` 三档：

- **笼统**：这个年级、这个科目会碰到类似的事，对不上具体课题也行
- **主题**：和课本里的一个主题是同一件事，仍然不写课时
- **拓展**：课文没有这一课，借这个科目的想法来讲

纯技术试验不是知识点，写 `"版本": "不对应课文"`，`状态` 用 `内部`，页面 `发布` 用 `不发布`。这种页不会进网站。给小朋友看的页面不能靠这一种写法躲过标注。

已有标注：

| 文件夹 | 状态 | 人教版 |
| --- | --- | --- |
| `states-of-matter` | 可讲。三维页在线，平面页只在压缩包 | 初中八年级物理「物态变化」（主题）；小学中年级科学「水的三态」（笼统） |
| `sorting-visualizer` | 草稿，不发布 | 初中信息科技「算法」（拓展，不限年级） |
| `fractal` | 草稿，不发布 | 小学高年级数学「图形与规律」（拓展） |
| `svg-demo` | 内部试验 | 不对应课文 |

草稿改成可讲之前，先自己对着页面讲一遍，再把 `状态` 改成 `可讲`，并把要给人看的页改成 `在线` 或 `仅下载`。

## 加一个动画

1. 新建文件夹，放一个 html。
2. 同目录写 `meta.json`。`id` 与文件夹名相同。文件夹里每一个 html 都要出现在 `页面` 里。
3. 用浏览器打开这个 html，把按钮都点一遍。手机宽度也看一眼。
4. 在仓库根目录运行 `npm run build`。缺标注、年级科目写错、html 没登记，构建会失败，并指出哪一份 `meta.json`。
5. 打开 `release/index.html`，确认首页上的年级、科目是你想给老师看的那一句。

`meta.json` 示例：

```json
{
  "id": "water-cycle",
  "标题": "水循环",
  "一句话": "水蒸发上天，再变成雨落下来",
  "状态": "草稿",
  "课本": [
    {
      "版本": "人教版",
      "学段": "小学",
      "年级": "中年级",
      "科目": "科学",
      "主题": "水循环",
      "对应": "笼统",
      "说明": "讲蒸发和下雨。不写第几课。"
    }
  ],
  "页面": [
    {
      "文件": "index.html",
      "标题": "水循环",
      "说明": "蒸发、成云、下雨",
      "发布": "不发布",
      "要联网": false
    }
  ]
}
```

确认能讲了，把 `状态` 改成 `可讲`，`发布` 改成 `在线`。要联网的库（例如 three）把 `要联网` 写成 `true`。语音、图片放在该文件夹里，用相对路径；语音目录写进 `资源`，例如 `"资源": ["voice"]`。

`发布` 的含义：

- `在线`：出现在首页，也会进压缩包
- `仅下载`：只进压缩包，首页不放链接
- `不发布`：只留在源码里。`草稿` 和 `内部` 只能用这一种

## 页面怎么写

这些约定是为了让后来的人，包括不写程序、靠 AI 改页面的人，还能看懂、还能讲。

- 界面用中文，句子短。按钮写「讲解」「暂停」这种词
- 投屏和手机都要能用：字够大，按钮够大，不要只做鼠标悬停才出现的功能
- 深色背景。字体用 `-apple-system, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`
- 一个 html 解决一个知识点。公共框架、新的 npm 包，先不要加
- 已有页面头上的 `author`、`version`、`changelog` 不要删。小演示不必新加这三项
- 不要改 `build.mjs` 里的混淆选项。物理、绘制这种每帧都在跑的循环，不能打开控制流平坦化

## 部署 H5

页面是静态文件，不需要服务器。用 Chrome、Edge 或 Safari 打开。

### 构建

在仓库根目录：

```bash
npm install
npm run build
```

`release/` 里会有首页、混淆后的页面、语音、`catalog.json`、`使用说明.txt` 和 `.nojekyll`。`.nojekyll` 要留着，否则 GitHub Pages 会忽略部分文件。

先用浏览器打开 `release/index.html`，从首页点进每个在线页面，把讲解播一遍。这一步通过之前，不要发布。

### 放到网上

在线站是 `gh-pages` 分支的根目录。用单独的工作目录更新它，避免在源码目录里删文件：

```bash
git worktree add ../learn-anew-pages gh-pages
rsync -a --delete release/ ../learn-anew-pages/
```

到 `../learn-anew-pages` 里看 `git status`。确认这里只有做好的网页，没有 `node_modules`，也没有源码目录。然后：

```bash
git add -A
git commit -m "Publish the site."
git push origin gh-pages
```

回到源码目录，删掉这个临时工作目录：

```bash
git worktree remove ../learn-anew-pages
```

仓库的 Pages 设置保持：分支 `gh-pages`，目录 `/`（根）。推上去之后打开 <https://luckinov.github.io/learn-anew/>。

`rsync --delete` 只会清那个临时目录。不要在源码仓库里对 `release/` 以外的目录这样删。

### 做成压缩包

```bash
cd release && zip -r ../learn-anew-obfuscated.zip . && cd ..
```

把 `learn-anew-obfuscated.zip` 上传到 GitHub Releases。不要把压缩包提交进仓库。解压后双击 `index.html` 就能看。标了要联网的页面，第一次打开仍要联网；语音已经打在包里。

## 构建会拦住什么

根目录里，只要文件夹中有 html，就必须有合法的 `meta.json`。下面这些情况会失败：

- 没有课本，或版本不是「人教版」也不是「不对应课文」
- 年级和学段对不上，例如小学写成八年级
- 科目不在常用名单里
- 文件夹里的 html 没有全部写进 `页面`
- 草稿、内部页面却写成了在线
- 讲解目录有 `manifest.json`，但里面没有句子

失败信息会写明是哪一个文件夹。先改 `meta.json`，不要为了让构建通过去改检查本身。
